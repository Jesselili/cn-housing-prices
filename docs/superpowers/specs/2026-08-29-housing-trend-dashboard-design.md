# 房价趋势 Dashboard 设计

日期：2026-08-29

## 目标

搭建一个基础房价趋势 dashboard，读取 `data/house_price_index_all.csv`，默认展示北京、上海、广州、深圳、长沙的二手住宅累计趋势，并允许用户在右上角新增或删除城市。用户可以切换到新建住宅；切换后每个城市按户型分别展示趋势。

本期不涉及 `examples` 目录。该目录只作为用户明确提及时的参考项目，不参与运行时读取、构建或复制。

## 已确认口径

- 默认住宅类型：二手住宅。
- 趋势指标：`metric=环比` 且 `base=上月=100`。
- 累计计算：每条序列首个有效月份为 100；后续月份为 `上一个累计值 × 当月 value / 100`。
- 默认城市：北京、上海、广州、深圳、长沙。
- 二手住宅：使用 `size_band=全部`，每个城市一条线。
- 新建商品住宅：按 `size_band` 拆为 `90m2及以下`、`90-144m2`、`144m2以上` 三条线/城市。
- 时间范围：默认展示 CSV 中全部可用月份（2011-02 至 2026-07，以实际数据为准）。

## 交互与界面

页面包含一个趋势卡片：

- 左侧标题为“房价趋势”。
- 右侧为住宅类型切换：二手住宅 / 新建住宅。
- 右侧为城市多选器：已选城市显示为可删除标签；打开选单后可勾选其他城市或取消当前城市。
- 图表为响应式 SVG 折线图，包含时间轴、累计指数纵轴、水平网格线和图例。
- 悬停图表时显示当前月份，以及该月份各可见序列的城市、户型和累计指数。
- 二手住宅按城市使用不同颜色；新建住宅沿用城市颜色，并用不同线型区分三个户型。
- 窄屏下控件允许换行，图表保留最小可读宽度并支持横向查看；不改变数据和交互逻辑。

## 数据流与模块边界

采用 React + TypeScript + Vite。图表仍使用原生 SVG，不引入额外图表库；React 负责组件拆分和筛选状态管理，TypeScript 负责约束 CSV 行、趋势序列和筛选状态的结构。

1. React 应用加载时从 `data/house_price_index_all.csv` 获取文本。
2. CSV 解析器处理 UTF-8 BOM 和带引号字段，转换为带类型的结构化记录。
3. 数据 selector 先按已确认口径过滤，再以城市、住宅类型、户型分组并按月份排序。
4. 累计计算层为每个分组生成 `{ period, value }` 序列；缺失值不伪造，交给绘图层形成断点。
5. React reducer 维护 `housingType`、`selectedCities` 以及可扩展的筛选状态；新增筛选项只增加状态字段和对应 action，不把条件散落在组件事件里。
6. 组件根据 selector 结果渲染 SVG、图例和 tooltip；状态变化只重新计算可见序列并更新图表。

建议的文件职责：

- `index.html`：页面入口。
- `src/main.tsx`：React 应用入口。
- `src/App.tsx`：加载数据、组合筛选状态和页面布局。
- `src/data.ts`：CSV 解析、数据过滤、累计计算和可见序列 selector。
- `src/filterState.ts`：筛选状态类型、默认值和 reducer，为后续多重筛选保留单一入口。
- `src/components/CityPicker.tsx`：城市标签、增删和多选菜单。
- `src/components/HousingTypeToggle.tsx`：住宅类型切换。
- `src/components/TrendChart.tsx`：响应式 SVG 趋势图、图例和 tooltip。
- `src/styles.css`：布局、颜色、响应式和交互状态。
- `tests/`：使用 Vitest 对数据层和筛选 reducer 做最小行为测试。

## 错误与边界

- CSV 加载失败：在图表区域展示明确的加载错误，不显示假数据。
- CSV 为空或缺少所需字段：展示数据不可用状态。
- 某城市或户型没有符合口径的数据：该序列不绘制，并在图表状态区提示无可用数据。
- 删除最后一个城市：允许操作，但展示空状态并提示至少选择一个城市可恢复趋势图。
- 多城市和新建住宅的线条较多：图例显示完整名称，tooltip 显示完整城市和户型，线型和颜色保持可区分。
- 数据中的 `value` 无法解析为数字：该数据点视为缺失，不阻塞其他序列。

## 测试与验收

实现前先写出会失败的测试，至少覆盖：

- 解析带 UTF-8 BOM 的 CSV，并正确读取字段。
- 过滤出环比、上月=100、目标住宅类型和目标户型。
- 一条序列首月归一为 100，后续值按环比连乘。
- 二手住宅每个城市只产生一条 `全部` 序列。
- 新建住宅每个城市产生三个户型序列。
- 切换住宅类型和增删城市后，可见序列集合与状态一致。
- 筛选 reducer 新增和删除城市时保持顺序且不产生重复值。

手工验收：

- 首次打开能看到北京、上海、广州、深圳、长沙五条二手住宅趋势线。
- 删除一个城市后对应线、图例和 tooltip 一起消失；重新勾选后恢复。
- 切换到新建住宅后，五个城市各显示三种户型，图例和线型对应正确。
- 选择其他城市后图表更新，CSV 加载错误和无城市空状态可见。
- 在桌面和窄屏宽度下控件不溢出，图表可读。

## 非目标

- 不实现后台 API、数据库、用户账号、数据抓取和定时更新。
- 不实现除月份范围之外的时间分析、同比/累计平均切换、地图、排名或预测。
- 不修改或复制 `examples` 目录中的代码。

## 增量需求：日期与城市输入筛选

在已有二手住宅、新建住宅趋势页面中增加共同的月份范围筛选和城市输入匹配：

- 日期控件使用起始月份和结束月份两个 `input type=month`。
- 默认起始月份为 CSV 中最早可用月份，默认结束月份为 CSV 中最晚可用月份，因此默认仍展示全量数据。
- 不增加“重置”按钮；恢复全量通过手动选择两个边界月份完成。
- 起止月份都包含在结果中；日期范围不合法时，控件需要阻止提交或显示明确提示，不产生反向范围图表。
- 日期范围先作用于原始环比记录，再重新计算累计序列；每条序列在当前筛选范围内的首个月重新归一为 100。
- 城市选择器增加搜索输入框，使用包含匹配；输入“上”时显示“上海”，用户点击复选项后加入已选城市。
- 搜索为空时显示全部城市；搜索无结果时显示“没有匹配的城市”。搜索不会改变已选城市，城市菜单保持打开以便连续选择。
- 筛选状态继续由 `FilterState` 和 reducer 统一管理，日期和城市逻辑不散落在图表组件中。

增量测试至少覆盖：日期起止边界包含、筛选范围内首月归一为 100、默认全量范围、无效日期范围，以及城市关键词“上”匹配“上海”。
