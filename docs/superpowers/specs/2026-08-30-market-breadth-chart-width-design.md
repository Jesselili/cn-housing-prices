# 市场广度图表自适应宽度设计

## 目标

修复“市场广度趋势”模块在数据量较少时图表只占卡片左侧、右侧出现大片空白的问题。图表应优先利用卡片的可用宽度，同时保留较多时间点下的可读性。

## 方案

调整 `MarketBreadthModule` 的 SVG 宽度计算：

- 以图表滚动容器的可用宽度作为最小内容宽度，让较少的数据点也能铺满当前卡片。
- 以每个时间点的最小槽位宽度限制最大压缩程度；数据点较多时，SVG 可以超过容器宽度并通过现有横向滚动查看。
- 保持现有柱状图比例、颜色、交互提示、坐标轴和数据计算不变。
- 只调整桌面端图表布局，不新增移动端断点、移动端专用交互或移动端验收要求。

## 实现边界

- `MarketBreadthModule.tsx` 继续负责根据数据量计算 SVG 宽度，增加对容器可用宽度的读取。
- `styles.css` 只补充使图表容器能够传递可用宽度的布局规则，不改变其他模块的宽度。
- 不修改 CSV、市场广度统计口径、住宅类型筛选或趋势图筛选状态。
- 不引入图表库。

## 验收标准

1. 在新建住宅、数据点较少的户型下，图表横向内容不再固定停留在卡片左侧，右侧空白明显减少。
2. 在二手住宅、数据点较多的情况下，柱状图仍保持可读的最小宽度，超出卡片时可以横向滚动。
3. 图表的最新月份、图例、柱状图颜色、悬浮提示和时间轴标签行为不变。
4. 现有测试继续通过，`npm run build` 成功。
5. `examples/` 不读取、不修改、不提交。
