# LPR 趋势模块与页面数据域重组设计

## 目标

在现有中国 70 城住宅价格指数 Dashboard 中增加独立的 LPR 趋势模块，并将标题、副标题、房价口径说明、房价动态数据状态和全部 70 城相关模块统一包进一个“70 城住宅价格数据”大模块。LPR 作为全国融资成本背景数据，独立于城市、住宅类型和房价日期范围筛选。

## 已确认的当前状态

- 项目使用 React、TypeScript、Vite 和原生 SVG，不引入图表库。
- 房价数据通过 `/data/house_price_index_all.csv` 加载，当前 `App` 只有一套房价加载状态。
- `DashboardIntro`、`DataStatusCard`、房价趋势、70 城横向比较、市场广度和最新环比目前在页面上平铺。
- `data/LPR.csv` 已存在，字段为 `发布日期`、`1年期LPR利率(%)`、`5年期LPR利率(%)`；当前文件有 85 条数据记录，日期范围为 `2019-08-20` 至 `2026-08-20`，文件按最新日期倒序排列。
- LPR 文件的日期字段与逗号之间存在制表符，现有 CSV 解析器的字段裁剪逻辑可以读取该字段；LPR 解析仍需显式验证字段和数值，避免依赖隐含列位置。

## 范围

### 包含

- 加载 `data/LPR.csv` 并将其作为独立数据源处理。
- 绘制 1 年期和 5 年期 LPR 历史趋势。
- 在图表模块中展示 LPR 口径说明和 LPR 与房市关系的四点解释。
- 为 LPR 模块提供加载中、加载失败、空数据和正常展示状态。
- 将现有 70 城相关内容包进一个外层大模块。
- 为数据解析、图表计算、模块渲染和页面分组增加测试。
- 保持房价现有筛选、数据口径、图表和移动端样式行为不变。

### 不包含

- 不让 LPR 跟随房价趋势的城市、住宅类型或日期范围筛选。
- 不把 LPR 当作房价序列或与房价指数合并计算。
- 不增加 LPR 预测、房贷月供计算、个人贷款利率计算或政策因果判断。
- 不增加外部数据源、远程 API 或图表库。
- 不修改 `data/LPR.csv` 的内容，不覆盖或删除现有未跟踪文件。
- 不新增移动端专门布局、交互或验收要求。

## 用户界面设计

页面由两个数据域组成：

```text
页面
├── 70 城住宅价格数据大模块
│   ├── 标题
│   ├── 副标题
│   ├── 房价口径说明
│   ├── 房价数据状态卡
│   ├── 房价趋势
│   ├── 70 城横向比较
│   ├── 市场广度趋势
│   └── 最新环比
└── LPR 数据大模块
    ├── LPR 趋势图
    └── LPR 口径说明
```

外层 70 城大模块只负责数据域的视觉分组和语义标识，不改变子模块自身的状态、筛选和图表交互。子模块原有的卡片边界可以保留，以降低对现有布局的影响；外层模块提供统一的背景、边框、圆角、内边距和模块间距。

LPR 模块使用独立的标题“LPR 利率趋势”，副标题动态显示 CSV 的有效记录数量和日期范围。图表下方固定显示口径说明，不使用弹窗或折叠交互。

## LPR 文案

模块的主说明使用以下含义，具体排版可匹配现有口径说明样式：

> LPR（贷款市场报价利率）是银行贷款定价的参考利率，不是房价。5 年期 LPR 更接近长期住房贷款，是观察房贷融资成本的重点指标。LPR 下调通常会降低部分借款人的利息负担，但不会直接决定房价上涨。

四点解释为：

1. **已经在还贷的人：**如果房贷合同采用 LPR 定价，到了重定价日后，利率下调可能让月供减少；具体金额取决于合同、加点和重定价日。
2. **想买房的人：**利率下降会降低利息，但购房决定还取决于房价预期、收入和就业稳定性；降息不等于购房需求必然回升。
3. **手里有闲钱的人：**当存款和理财收益下降时，部分人可能更愿意比较提前还贷；是否划算还要看贷款利率、资金流动性和合同条款。
4. **对整个房市的信号：**降 LPR 是降低融资成本、托底需求和防范风险的政策信号，但不是房价上涨的充分条件；市场能否回暖仍取决于收入、就业、预期和房屋需求。

文案中的“可能”“通常”“部分人”等限定词必须保留，避免把利率变化直接表述为房价或购房需求的确定性因果。

## 数据模型与数据流

在 `src/data.ts` 中增加独立于 `CsvRow` 的类型：

```ts
export interface LprPoint {
  publishDate: string;
  oneYearRate: number;
  fiveYearRate: number;
}
```

增加纯函数：

```ts
export function parseLprCsv(text: string): LprPoint[];
```

`parseLprCsv` 的行为：

- 移除首字段 BOM，并按表头名称读取三列，不依赖输入文件的行顺序。
- 对日期、1 年期和 5 年期字段进行裁剪和数值转换。
- 丢弃日期为空或任一利率不是有限数字的记录。
- 按 `publishDate` 升序返回；同日期记录只保留第一条，避免图表出现重复日期点。
- 空文本、只有表头或没有有效记录时返回空数组，不抛出渲染层无法处理的异常。

`App` 保留现有房价加载流程，同时新增独立的 LPR 加载状态：

```ts
type LprLoadState = 'loading' | 'ready' | 'error';
```

LPR 请求使用 `/data/LPR.csv`。房价加载失败不应让 LPR 模块进入错误状态，LPR 加载失败也不应隐藏 70 城模块。两套数据的 `loadedAt` 和错误信息分别维护。

## 图表设计

`src/components/LprModule.tsx` 负责展示和交互，数据计算留在 `src/data.ts`。

- 使用原生 SVG 绘制两条折线。
- 5 年期 LPR 使用更醒目的主色和较粗线宽；1 年期使用辅助色。
- 纵轴单位为 `%`，刻度覆盖当前有效数据的最小值和最大值，并保留可读的上下边距。
- 横轴按发布日期升序排列，稀疏数据用年份或关键日期标签，避免 85 个日期标签重叠。
- 采用现有响应式图表宽度和横向滚动模式：数据点较少时填满卡片，数据较密集时保留每点最小槽宽。
- 通过指针悬停显示发布日期、1 年期利率和 5 年期利率；SVG 同时提供 `title` 和 `desc`。
- 图表没有筛选控件，避免暗示 LPR 属于城市房价筛选维度。
- 没有有效数据时显示明确的空状态；加载或请求失败时显示独立状态提示。

## 页面集成

`App.tsx` 的返回结构改为：

```tsx
<main className="page-shell">
  <section className="housing-dashboard-module" aria-labelledby="dashboard-title">
    <DashboardIntro />
    <DataStatusCard ... />
    <section className="trend-card">...</section>
    <CityComparisonMatrix ... />
    <MarketBreadthModule ... />
    <MonthOverMonthModule ... />
  </section>
  <LprModule loadState={lprLoadState} points={lprPoints} error={lprLoadError} />

```

`DashboardIntro` 继续负责标题、副标题和房价方法论说明；`DataStatusCard` 继续负责动态房价覆盖信息。LPR 不复用房价 `DataStatusCard`，避免把两种数据源的范围和更新时间混在一起。

新增样式只覆盖外层数据域、LPR 模块和 LPR 图表，不修改现有移动端媒体查询的行为。若外层包裹导致现有子模块的 `margin-top` 出现重复，只调整由本次包裹直接造成的桌面间距，不重做子模块布局。

## 错误处理

- 房价和 LPR 各自显示独立的加载中、错误和空数据状态。
- HTTP 非成功响应视为对应数据源加载失败，并显示“请检查本地开发服务是否从项目根目录启动”等现有风格提示。
- LPR CSV 字段不完整或有效记录为空时，模块显示不可用状态；不阻断房价数据展示。
- 解析过程中不补值、不插值、不把利率变化转换为房价变化。

## 测试与验收标准

### 数据层

- LPR 表头 BOM 能正确处理。
- 当前文件的 85 条记录能够解析为 85 个有效点，并按日期升序返回，首尾日期为 `2019-08-20` 和 `2026-08-20`。
- 数值字段会转换为数字；空值、非数字值和空日期会被排除。
- 重复日期只保留一个点。
- LPR 解析不会改变现有 `parseCsv`、房价筛选和趋势计算行为。

### 组件层

- 正常状态下显示两条线、图例、动态范围和口径说明。
- 5 年期文案和视觉标识明确为重点观察对象。
- 模块加载中、错误和空数据状态可独立渲染。
- LPR 模块不接收也不使用房价城市、住宅类型和日期范围筛选状态。
- 外层 70 城模块包含标题、副标题、房价口径说明、数据状态卡及全部现有 70 城模块。

### 工程验证

- `npm test` 全部通过。
- `npm run build` 通过 TypeScript 检查和 Vite 生产构建。
- `git diff --check` 无空白错误。
- 不读取、修改或删除 `examples/`。
- 不覆盖或删除 `data/LPR.csv`。

## 取舍

选择“独立 LPR 模块 + 70 城外层分组”的原因是：LPR 是全国融资成本背景变量，与城市房价指数的观察对象和筛选维度不同；独立数据流能够避免指标混用，外层分组又能保留当前各 70 城子模块的成熟交互。把 LPR 合并进数据状态卡或让它共享房价筛选，会降低数据边界的可读性并增加误解风险。
